# AI-buddy

Помощник стажёра при первом запуске сервиса. Сверяет документацию,
объясняет расхождения, предлагает подтверждённую инструкцию и создаёт
обращение наставнику, когда нужна помощь человека.

## Запуск и проверка

Требуются Docker Desktop/Engine и Docker Compose v2. GPU и API-ключ для
основного сценария не требуются.

```bash
cp .env.example .env
docker compose up --build -d
```

Открыть **http://localhost:3000**.
Учётная запись: **intern@example.com**, пароль **DemoPassword123!**.
Настройки `.env.example` предназначены для локальной проверки.

Для демонстрации без прежней переписки можно создать отдельную учётную запись,
сохранив существующие данные:

```bash
docker compose run --rm -e SEED_EMAIL=judge@example.com seed
```

Вход: `judge@example.com`, пароль из `SEED_PASSWORD` (по умолчанию `DemoPassword123!`).

| Запрос в чате                                                     | Ожидаемый результат                                                                                                                                                                                         |
| ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Не запускается listing-search: ошибка версии Python | Python 3.12 подтверждён конфигурацией текущей ревизии; показано расхождение с Confluence; создана задача владельцам документации |
| Не помогло                                                          | Создано обращение наставнику с контекстом                                                                                                                                                |
| Не скачивается notifications-service                            | Объяснено отсутствие доступа; закрытый документ не раскрыт; создано обращение наставнику                                                         |
| Не запускается billing-service                                  | Конфликт версий без надёжного подтверждения; вопрос передан наставнику                                                                                          |

Источники открываются прямо в ответе. Кнопка **«Обращения»** показывает
сохранённые номера, статусы, время и контекст. После обновления страницы и
перезапуска приложения данные сохраняются.

## Данные и интеграции

Данные, сотрудники и инструкции синтетические и не являются регламентами Авито.
Confluence и Git представлены локальным корпусом в `ai_service/data/`;
корпоративный трекер имитируется реестром SQLite. Заявки сохраняются,
но реальные уведомления сотрудникам и действия во внешних корпоративных
сервисах не отправляются. Матрица доступов моделирует роли `intern` и `mentor`.

## Модель и задержка

LLM **Qwen3 4B Instruct**, сборка `qwen3:4b-instruct-2507-q4_K_M`,
[Apache 2.0](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M),
используется при подготовке фактов из документов, а не на каждом сообщении.
Это устраняет повторное чтение одних и тех же инструкций и зависимость
интерактивного ответа от скорости локального CPU.

В репозитории приложен индекс `ai_service/data/facts.json`, полученный реальным
запуском Qwen. В нём — факты и проверенные цитаты, а не готовые ответы на вопросы.
Для каждого документа проверяется SHA-256 содержимого и метаданных. Изменённый
документ не использует устаревшие факты. Явные параметры дополнительно читаются
правилами; при недостатке подтверждений создаётся обращение наставнику.

По умолчанию `AI_MODE=indexed`. Прежнее значение `llm` также поддерживается
как совместимый режим чтения индекса. `offline` включает только правила.
Происхождение и покрытие индекса доступны во внутреннем `/health` AI-сервиса.

В кейсе ориентир **<1 с относится к простым локальным действиям интерфейса**.
Вызовы LLM могут занимать больше времени при корректном отображении ожидания.
Подготовка индекса вынесена из пользовательского запроса; её длительность
измеряется отдельно от задержки ответа. Метрики конкретного прогона —
в [docs/VALIDATION.md](docs/VALIDATION.md).

### Пересоздать индекс настоящей локальной моделью

```bash
docker compose --profile llm run --build --rm indexer
docker compose restart ai
```

Compose запускает Ollama, скачивает выбранную модель и сохраняет новый индекс
в volume. Загрузка весов около 2,5 GB выполняется один раз; память нужна также
для контекста и вычислений. Локальная подготовка поддерживает CPU. После неё
модель можно остановить: `docker compose stop ollama`.

Изменили документы: пересоберите `ai` и `indexer`, подготовьте новый индекс,
затем перезапустите `ai`:

```bash
docker compose build ai indexer
docker compose --profile llm run --build --rm indexer
docker compose up -d --no-deps ai
docker compose restart ai
```

### Использовать внешний API

Нужен OpenAI-совместимый `/chat/completions` с JSON mode. Установите в `.env`
`LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`. Ключ не коммитится.
Индекс можно подготовить без запуска локальной модели:

```bash
docker compose run --rm --no-deps ai python -m buddy.index
docker compose restart ai
```

При ошибке API или неверных фактах старый индекс не перезаписывается.
Таймаут подготовки 120 с на вызов, не более двух попыток на группу документов.
Интерактивный ответ не делает сетевого вызова LLM.

## Реестр обращений

Основное хранилище: `/state/tracker.sqlite` в volume `tracker_data`.
Читаемый журнал: `/state/tickets.jsonl`, одна JSON-запись на обращение.
Журнал восстанавливается из SQLite при запуске; повтор того же request_id
не создаёт второе обращение. Конфликты документации дедуплицируются по
пользователю, сервису, ревизии и содержимому расхождения.

```bash
docker compose exec ai cat /state/tickets.jsonl
```

В браузере `/api/v1/ai/tickets` доступен только с JWT и показывает обращения
текущего пользователя. Подключить реальный трекер можно заменой адаптера
сохранения и маршрутизации получателей.

## Архитектура и права

React/TypeScript → Go HTTP API → Python/FastAPI → индекс фактов и SQLite.
Go хранит пользователей/историю в PostgreSQL и получает роль из БД.
Python фильтрует документы по правам **до** чтения фактов и выдачи источников.
Модель не управляет доступами и не исполняет команды из документов.
Версионный конфликт разрешается только подтверждением машинной конфигурации
той же ревизии; свежесть и большинство копий не считаются доказательством.
Неопределённость, отсутствие инструкции или запрос человека → наставник.
Статус «Решено» означает предоставленную инструкцию; подтверждение успешного
запуска у пользователя — следующий шаг, не доказанный результат.

Спецификация: [specs/001-onboarding-assistant.md](specs/001-onboarding-assistant.md).
Контракт публичного API: [api/openapi.yaml](api/openapi.yaml).

## Тесты

Python 3.12+, uv; Node 24; Go 1.27.3+. Зависимости закреплены
в `uv.lock`, `package-lock.json`, `go.mod` и `go.sum`.

```bash
# Приёмочные сценарии и задержка Python-сервиса из готового контейнера
docker compose exec ai python evaluate.py --mode indexed

# Сквозная проверка HTTP, входа, прав, истории, источников и заявок
docker compose run --rm --no-deps -v "$PWD/scripts:/checks:ro" ai python /checks/smoke.py http://frontend

# Unit-тесты Python и покрытие
docker compose run --rm --no-deps -e UV_PROJECT_ENVIRONMENT=/tmp/buddy-tests -v "$PWD/ai_service:/src" -w /src ai uv run --frozen --group dev pytest --cov=buddy --cov-report=term-missing
```

Фронтенд: `cd frontend && npm ci && npm run test:coverage && npm run build`.
Go: `cd backend && go test -coverpkg=./... -coverprofile=coverage.out ./...`.
Без `TEST_DATABASE_URL` интеграционный тест Go явно пропускается.
Для полного покрытия с настоящей PostgreSQL, AI и процессами API/seed:
`TEST_DATABASE_URL=postgres://... uv run --project ai_service --all-groups python scripts/verify_stack.py`.
Нужны Go в PATH, отдельная тестовая БД и свободные порты 8001/8080.
Скрипт создаёт собственную временную схему и удаляет только её.

Результаты и отчёты покрытия: [docs/VALIDATION.md](docs/VALIDATION.md),
[docs/COVERAGE.json](docs/COVERAGE.json), `docs/test-reports/`.
Покрытие кода и прохождение небольшого приёмочного набора не являются
оценкой точности на всём массиве документации.

## Остановка и материалы сдачи

`docker compose down` останавливает приложение с сохранением данных.
`docker compose down -v` удаляет volumes, включая историю, заявки и веса.
Миграции автоматически применяются при первом создании базы.
При обновлении существующей схемы их нужно применять отдельно.

Пилот: оценивать время наставников на типовые вопросы, подтверждённую долю
решённых обращений, повторные обращения, время до первого PR, утечки прав
и задержку. Экономия времени и денег требует измерения на стажёрах.
