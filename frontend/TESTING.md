## Состав расчёта и исходные пробелы

В исходной конфигурации не было явного `coverage.include` и порога; неимпортированные модули могли не попадать в расчёт. Исходные тесты уже проверяли API, SSE, auth/chat-хуки и маршруты через тестовую страницу, но не настоящий `ChatPage`, меню пользователя и тему. Также отсутствовали тесты точки входа и рабочего `App`/BrowserRouter.

Теперь `coverage.include` — `src/**/*.{ts,tsx}`: в расчёт включены все соответствующие прикладные файлы, даже не загруженные тестами. Не исключены страницы, собственные компоненты, контексты, хуки, API, `main.tsx`, маршрутизация и локальные `components/ui/`. Включены даже `src/mocks/`: они используются в демонстрационном режиме приложения и не являются исключительно тестовыми фикстурами.

Явно исключены только:

| Шаблон | Причина |
| --- | --- |
| `src/**/*.test.{ts,tsx}` | Сами тесты |
| `src/**/*.spec.{ts,tsx}` | Альтернативное именование тестов |
| `src/test/**` | MSW test server, setup и эмуляция браузерных API для тестов |
| `src/**/*.d.ts` | Декларации типов без исполняемого кода |

`node_modules`, `dist`, `coverage` и сгенерированный `public/mockServiceWorker.js` находятся вне `src/**/*.{ts,tsx}`. CSS, SVG и шрифты не являются TS/TSX-кодом и не входят в V8-расчёт. `types/auth.ts`, `types/chat.ts`, `lib/utils.ts` и `pages/index.ts` остаются в наборе файлов; чистые типы и реэкспорты не добавляют исполняемых строк.

## Изоляция и ограничения

UI-компоненты не подменяются массовыми моками: тесты используют настоящий Markdown, Base UI, формы, чат, меню, Context и хуки. В `main.test.tsx` подменены границы запуска — `createRoot` и запуск worker; это позволяет проверить порядок bootstrap без повторного монтирования целого приложения. Само приложение и маршрутизация проверяются отдельно без этих подмен.

Все HTTP-запросы перехватывает MSW; необработанный запрос приводит к ошибке теста, а не к обращению к реальному backend. Для проверки промежуточного состояния SSE тест вручную передаёт события через контролируемый ReadableStream. Не используется ожидание случайной продолжительности генерации.

Перед тестами очищаются cookies, localStorage, тема и состояние системных media queries. После — DOM, временные MSW-обработчики, globals и таймеры. В jsdom эмулированы отсутствующие `matchMedia`, `ResizeObserver` и `scrollTo`. MediaQueryList сохраняет реальные подписки и события для проверки темы. Эмуляция не заменяет проверку физической геометрии скролла, CSS-анимаций или визуальную проверку в браузере.

Меню проверяется в том числе клавиатурой: jsdom не рассчитывает геометрию вложенных pointer-меню. Низкоуровневый `fireEvent` используется только для IME, storage и специальных keyboard-событий, которые нельзя полноценно воспроизвести через user-event.
